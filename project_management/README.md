
# Project Management

This directory contains the project management documentation for the Pac-Man activity.

Its purpose is to provide evidence of a structured development process, including planning, task distribution, risk identification, testing strategy, progress tracking, and technical decisions.

The documentation is organized into the following files:

| File | Description |
|---|---|
| [01 — Project Overview](./01_PROJECT_OVERVIEW.md) | Project objectives, scope, deliverables, and technical approach. |
| [02 — Project Timeline](./02_PROJECT_TIMELINE.md) | Development phases and progress compared with the initial plan. |
| [03 — Team Organization](./03_TEAM_ORGANIZATION.md) | Team responsibilities, collaboration, and decision-making. |
| [04 — Risk Analysis](./04_RISK_ANALYSIS.md) | Potential project risks and mitigation strategies. |
| [05 — Test Plan](./05_TEST_PLAN.md) | Acceptance criteria and test scenarios for the game. |
| [06 — Progress Report](./06_PROGRESS_REPORT.md) | Current implementation status and available evidence. |
| [07 — Blockers and Decisions](./07_BLOCKERS_AND_DECISIONS.md) | Technical challenges, design decisions, blockers, and lessons learned. |

## Project Management Approach

The project is organized into development phases, starting with understanding the requirements and planning the architecture, followed by implementation, integration, testing, packaging, and documentation.

Tasks are divided between the two team members according to their areas of responsibility. Technical decisions are documented to make the implementation easier to understand and review.

The project management documents cover the areas requested in Chapter 8 of the subject:

- Project planning and timeline.
- Progress tracking.
- Project analysis and technical decisions.
- Risk analysis and mitigation.
- Team organization and responsibilities.
- Acceptance testing.
- Blocking points and technical challenges.

## Documentation Accuracy

This documentation describes the available project information and the development approach.

Historical dates, meeting records, test execution results, and other details are included only when supported by available evidence. Information that was not recorded is explicitly identified rather than reconstructed or invented.
